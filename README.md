# Сметчик — локальный сметный отдел

Создан 09.09.2026 по поручению Алексея. Репозиторий: [vetus-nauta/smeta](https://github.com/vetus-nauta/smeta). Локальная рабочая копия: `/home/alexey/Groot/smetchik`. Рабочее имя этого направления и чата: **Сметчик**. Это локальная база знаний и процедур для работы Codex; она не означает получение диплома, изменение весов модели или фактическое переименование чата в интерфейсе.

## Как начать работу

Достаточно поручения: «Сметчик, создай проект …», «Проверь эту смету», «Подготовь КП» или «Сделай КАЦ по этим предложениям». Начальник отдела читает [правила](AGENTS.md), создаёт паспорт, распределяет работу и выпускает результат после проверки. Файлы можно положить в `projects/<код>/input/`; оригиналы сохраняются.

Без региона, уровня цен, вида работ, объёмов и требований заказчика можно подготовить структуру и запрос недостающего, но нельзя выдать обоснованную итоговую сметную стоимость. Неизвестные цены и нормативы не заменяются нулями.

Команды выполняются без установки дополнительных пакетов:

```bash
python3 /home/alexey/Groot/smetchik/tools/office.py new DEMO-002 --name 'Название объекта'
python3 /home/alexey/Groot/smetchik/tools/office.py list
python3 /home/alexey/Groot/smetchik/tools/office.py check DEMO-002
```

Новый проект — черновик. `check` проверяет комплектность, но не утверждает стоимость. Реестр SQLite можно восстановить по файлам; первичные документы и решения остаются в папках проектов.

## Состояние подготовки

База v1 подготовлена для последующей практической работы с документами. [Статус и ограничения](office/readiness.md) отличают изученные источники, проверенную арифметику и операции, ещё не выполненные в лицензированной ГРАНД-Смете. Перечень источников не является гарантией отсутствия более поздних изменений: редакция и применимость перепроверяются для каждого проекта.

Результаты сборки и проверки: [приёмка офиса](checks/office-acceptance.md).

Дополнение 09.09.2026: [интеграция практического опыта из Google Drive](knowledge/practical-integration.md) — СВОР/УТВ, увеличение/уменьшение, ФЕР/ФССЦ, проверенные XML-поля, ошибки и переговоры. Добавлен навык `smeta-changes`; эталонный набор теперь состоит из пяти навыков.

Правила, изменения дисциплин и утверждённые XML фиксируются локально и в GitHub по [регламенту](office/repository.md). Внешняя отправка писем и запросов поставщикам в эту настройку не входит. Сотрудники — роли ИИ, вызываемые начальником для конкретной задачи; постоянно работающие фоновые процессы не установлены.

## Работа через репозиторий

Правила и навыки изменяются с записью в [CHANGELOG.md](CHANGELOG.md) и коммитом. Эталонные навыки лежат в `skills/`, установленные копии на этом ПК — в `~/.codex/skills/`. [Архив XML](products/README.md) содержит только утверждённые версии; пока реальных XML нет.

После клонирования: `python3 tools/office.py init`, затем `python3 tools/office.py index-sources`. SQLite — локальный производный реестр, исключённый из Git; первичные инструкции и реестры источников входят в репозиторий. Рабочие исходники/черновики в projects/ не публикуются автоматически. Проверка инструментов: `python3 -m unittest discover -s checks -p 'test_*.py' -v`.

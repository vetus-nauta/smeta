# ГРАНД-Смета: подтверждённая семантика XML

Проверено 09.09.2026 по официальной схеме **OpenXML_LS_2026.1.1**. [Источник](https://xsd.grandsmeta.ru/ls/ls.zip), [локальная схема](../sources/grand-openxml/OpenXML_LS_2026.1.1.xsd), [происхождение и хеши](../sources/grand-openxml/manifest.json).

| Поле / тип | Значение в этой схеме | Следствие для проверки |
|---|---|---|
| `APositionInfo/@SysID` | Системный идентификатор сохраняется при перемещении и перенумерации | Не подменять печатным номером |
| `Number` | Номер позиции для представления | Не считать устойчивой связью |
| `MaxSysID` | Максимальный системный идентификатор позиций | Не приравнивать числу строк |
| `APositionInfo/@Quantity` | Строка с результирующей формулой физического объёма либо числом | Запрет всех формул или требование только формул неверны |
| Дочерний `Quantity` / `TQuantity`, группа `AQuantity` | `Fx`, `Result`, `KUnit`, `KMult` описывают формулу, результат и кратности | Не смешивать одноимённые атрибуты и элементы |
| `TResourseOptions/NotCount`, `NotCountedResSysID` | Штатный признак и связь неучтённого ресурса | Не удалять их массово ради нулевого счётчика |

Схема допускает значения и структуру; правильность арифметики и ресурсоучёта нужно проверять отдельно. Это схема локальной сметы программы, не универсальная схема GGE и не спецификация подписи GSFX. Наличие XSD на диске не означает, что какой-либо производственный XML ею проверен.

## Объёмы в интерфейсе

Разработчик различает ввод количества в измерителе расценки и физического объёма со знаком `=` с учётом кратности программой. Поэтому умножение/деление нельзя переносить между режимами механически. [Официальная справка](https://help.grandsmeta.ru/objomy-rabot-v-smete/raschjot-ob-jomov-rabot/kak-zadat-ob-jom-rabot-v-naturalnykh-edinitsakh-izmereniya).

Рабочая проверка: физический объём → выбранный режим/единица → количество в документе → отображение после импорта → обратная выгрузка. Совпадение формулы с её кэшированным результатом не исключает систематическую ошибку масштаба.

## Неучтённый ресурс

Справка описывает связь уточнённого материала с исходной строкой неучтённого ресурса и её значение для дальнейшей работы. Сохранённая исходная строка сама по себе не доказывает двойной оплаты; проверяются способ учёта и связь. [Официальная справка о связи ресурсов](https://help.grandsmeta.ru/rabota-s-resursami/rabota-s-resursami-v-smete/neuchtjonnye-zatraty/svyaz-dobavlennogo-materiala-s-iskhodnoj-strokoj-neuchtjonnogo-resursa).

## Что не установлено

Точное устройство и способ создания `Data.sign` не подтверждены найденной официальной документацией. Описания прежних авторов остаются частными наблюдениями. Любой извлечённый `Data.xml` нельзя автоматически объявлять поддерживаемым обменным XML. Использовать документированный экспорт и проверенный импорт; штатное сохранение не является подписью заказчика.

## Схема конъюнктурного анализа: проверка 09.09.2026

Официальный [архив КА](https://xsd.grandsmeta.ru/ka/ka.zip) содержит `OpenXML_KA_2026.1.1.xsd`. [Локальная копия и происхождение](../sources/grand-openxml-ka/manifest.json). Это отдельная схема от ЛСР. Тип документа — `{2B0470FD-477C-4359-9F34-EEBE36B7D354}`.

- `Supplier` предложения — порядковый номер контрагента, начиная с 1. При продолжении новые организации добавляются в конец, исходный порядок сохраняется.
- `Position/@Number` — номер КА, `Item/@Number` — номер по КП/прайсу. Их нельзя заменять номером строки Excel или порядком поставщиков без основания.
- `MainSubPosition` — выбранная вложенная позиция. Простое сравнение переписанных отпускных цен ещё не обосновывает выбор сметной цены.
- `aKA_Position` не содержит `Quantity`. Количество и пересчёт упаковки сохраняются в сопровождающей карте, произвольный атрибут не добавляется.
- `Storage` — процент ЗСР, `UseTransp` — участие транспорта в расчёте ЗСР. Неизвестная доставка не подтверждается отсутствием атрибута.
- `GrandSmetaSign` необязателен и описан как цифровая подпись. Старую подпись нельзя выдавать за подпись изменённой редакции; печатные реквизиты составителя и проверяющего — отдельный слой.
- `Attachments/Binary` допускает метаданные, но не текстовое base64-тело. Отдельный XML не переносит байты вложений GSFX. Подхват соседней папки при импорте требует фактической проверки программы.

На локальном исходнике версии 16.2 обнаружены расхождения с опубликованной XSD: `Mode2020Order=2026` при перечислении 2025/2024, превышение ограничения размера вложения и отсутствие обязательного по старой схеме `SupplierKind` у предложений. Это наблюдение на одном файле, не универсальное описание версии 16.2. Сначала проверяется неизменённый источник; исходные ошибки схемы отделяются от внесённых преобразованием. Нельзя менять дату методики, размеры файлов или объявлять внутреннюю адаптацию официальной схемой ради успешной валидации.

Для продолжения таблицы обязательно различать строку листа и номер ресурса. Повторы по помещениям не объединяются только по названию: единица, комплектность и цена могут различаться. Округление цены до копеек проверяется отдельно от формул исходной книги; влияние на сумму фиксируется, а не скрывается.

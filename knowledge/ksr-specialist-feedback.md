# Разбор КСР после ручной доработки

11.09.2026. Обезличенные выводы по обратной связи специалиста. Ручное заполнение — источник решений для анализа; его авторство само по себе не подтверждает правильность. Исходные клиентские файлы и построчная сверка остаются в локальном проекте.

## Как принимать доработанную версию

1. Сохранить исходный файл и SHA-256. Для GSFX прочитать содержимое контейнера, не считать расширение отдельным доказательством формата XML. Не редактировать оригинал и служебную подпись.
2. Сопоставить позиции по устойчивому SysID с проверкой наименования, единицы и состава. Номер строки и Number могут измениться после вставки или перезапуска нумерации раздела. В отчете дать старую позицию, новый порядковый индекс, Number и раздел.
3. Отдельно сверить количество предложений и их коммерческие ключи: поставщик, исходный документ, строка, описание, единица, цена. Вставка чужого предложения внутри правильной позиции может изменить минимум даже без потери прежних строк.
4. Для каждого заполненного KSRGroup проверить существование именно **группы** в зафиксированной версии каталога, затем книгу, часть, раздел, материал, назначение и предмет поставки. Формат записи и непустое поле недостаточны. Раздел нельзя считать сокращенной группой.
5. Сопоставить одинаковые ресурсы по всему документу. Различие кода допускается при доказанном различии исполнения/предмета поставки; случайное копирование или ошибка выбора — только гипотеза до проверки.
6. Проверить все вложенные предложения, код ТЦ и поле исходной строки. Изменение KSRGroup не доказывает обновление зависимых полей. Не переписывать цену по предполагаемому ошибочному минимуму при анализе чужой версии.
7. Для каждого решения разделить: факт внесенного кода; возможную логику автора; проверенный смысл каталога; техническое основание; итог «обосновано / условно / не соответствует / не является группой». Не приписывать специалисту неподтвержденные намерения.
8. В базу отдела переносить только проверенный принцип с областью применимости. Код не становится универсальным правилом для торговой марки или для всех строк одного КП.

## Проверенные ограничения каталога

Проверены по официальному КСР №44 (Доп_19, публикация14.08.2026); актуальность и идентичность файла повторно проверены11.09.2026. [Каталог ФГИС ЦС](https://fgiscs.minstroyrf.ru/ksr/navigate), [официальный XLSX](https://fgiscs.minstroyrf.ru/api/values/GetFileContentCache/fe2a4003-8175-45dc-9c5c-ca60fd2efaf2).

| Код | Смысл и ограничение |
|---|---|
| 01.5.02.04 | Панели шумозащитные в разделе дорожных ограждений. Совпадение слова «шум» не обосновывает интерьерную минеральную плиту или звукоотражающий элемент зала. |
| 09.2.01.05 | Декоративно-облицовочные конструкции в книге алюминиевых конструкций. Общее название последней строки не отменяет материала родителя. |
| 07.2.06.03 | Профили в элементах облицовки из черных металлов. Не универсальный код готовой панели, напыления, скобы либо полного смешанного комплекта подсистемы. |
| 01.7.06.01 | Ленты герметизирующие. Не подходит плите, панели или комплекту только из-за соседства с лентой в таблице. |
| 01.6.01.02 | Листы гипсокартонные. Панель на иной основе, подсистема и напыление не становятся ГКЛ. |
| 10.2.02.03 / 10.2.02.06 | Латунные листы / полосы в разделе полуфабрикатов. Готовое изделие не классифицируется автоматически по материалу заготовки; цвет «латунь» не устанавливает сплав. |
| 59.1.07.02 | Конструкции и детали строительных конструкций из черных металлов. Широкое название не снимает ограничения материала и требования определить комплектность. |
| 12.2.02 | Раздел звукоизоляционных материалов, а не группа. Нужна соответствующая предмету группа; дочерние группы этого раздела описывают панели, поэтому для матов и напыления выбор может потребовать другой ветви. Не дописывать произвольный суффикс. |
| 08.01.02 | В проверенной редакции не является группой КСР. Не исправлять автоматически в похожий код. |

## Что исправить в собственном подходе

Не смешивать полноту спецификации с достаточностью признаков для группы. Когда на уровне группы каталог не различает размеры или основу, не оставлять код пустым только по этой причине; фиксировать отдельно вопросы цены и технической сопоставимости. Например, группу готовых металлических ворот не следует ограничивать только сталью, если такого ограничения нет у родителя. Группу акустических стеновых панелей нельзя сужать до материала отдельных представителей. Подробности: [техническое исследование](ksr-technical-research.md).

При этом не закрывать неопределенность формальным заполнением: «латунь» уже подтверждает металл поручня, но не подтверждает поставку полосы; название декоративного эффекта не устанавливает основу листа; подсистема из профилей не тождественна отдельному профилю.

Критерий завершения проверки — не процент непустых кодов. Он включает существование группы, соответствие предмету, правильную связь с предложением и сохранность документа. XSD, каталог КСР и фактический пересчет программы — разные проверки.

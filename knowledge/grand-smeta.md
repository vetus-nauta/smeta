# ГРАНД-Смета: рабочий конспект отдела

Дата проверки: 2026-09-09. Статус: изучена перечисленная официальная документация; практический запуск, лицензия, установленные базы и контрольный расчёт на этом ПК этим конспектом не подтверждаются. Это авторская инструкция для работы, а не сертификат квалификации и не полная копия руководства. Правовую применимость норм определять по первичным нормативным источникам проекта.

## Версия и рабочее место

Карточка разработчика указывает **2026.2, Обновление 2, исполняемый файл 16.2.2**. Требования: x86-64, минимум 2 ядра от 2 ГГц, 8 ГБ RAM, экран 1920×1080, USB, от 2 ГБ диска плюс место под базы. Поддерживаются Windows 10/11 x64 и перечисленные разработчиком Linux: РЕД ОС 7.3/8.0, Альт 10.4/11.1, РОСА 12.5.1/13, AlterOS 7.5/9.5, Astra Linux SE 1.7/1.8 (стационарная версия). Совместимость иной ОС не предполагать. [Карточка продукта](https://www.grandsmeta.ru/product-grand-smeta).

Утилита загрузки устанавливает или обновляет программу и проверяет драйвер Guardant; доступны отдельные загрузчики Windows/Linux. Для новой версии требуется подходящая лицензия: установка файлов сама по себе её не предоставляет. Перед обновлением отдел сохраняет резервную копию пользовательских документов и фиксирует версию. [Загрузки](https://www.grandsmeta.ru/download), [официальное сообщение о лицензии версии 2026.1](https://shop.grandsmeta.ru/news/690-vypushchena-novaya-versiya-programmy-grand-smeta-versiya-2026-1).

| База знаний офиса | Этот каталог с инструкциями и источниками | Не считать установленной нормативной базой ГРАНД-Сметы |

В Windows стационарная установка обычно использует `C:\Program Files\GrandSmeta\` для программы; `C:\ProgramData\Grandsmeta\Data` для баз; рядом `Lic` для лицензий. Истинные пути смотреть через **Файл → Установки → Пути к файлам**. Папки лицензий не включать в публикуемые реестры. Начиная с 2025.2 есть папка **Мои сборники**; пользовательские сборники доступны вместе с нормативной базой. Пользовательское происхождение не превращает расценку в утверждённый норматив. В версиях 2026 развиваются ВОР, КА, смета контракта, пояснительная записка, экспорт. [Изменения версий](https://www.grandsmeta.ru/whatisthenewversion).

## Основной маршрут сметы

Перед вводом начальник утверждает паспорт: объект, вид работ, источник финансирования, регион/зона, метод, уровень цен, нормативная база, исходные чертежи и ВОР, требуемый формат выдачи. Без этих данных допускается только учебный черновик.

1. Создать объект и локальную смету; заполнить реквизиты и сохранить исходную версию.
2. Подбирать норму по технологии, составу работ, измерителю и технической части, затем вводить количество со ссылкой на ВОР. Название позиции само по себе недостаточно.
3. Проверить ресурсную часть: учтённые и неучтённые материалы, оборудование, единицы, замены и расход. Изменения объяснять в журнале.
4. Настроить метод расчёта, цены, индексы, коэффициенты и начисления; сформировать ведомость ресурсов.
5. Проверить сравнение с базой и предыдущей редакцией, затем подготовить выходные формы.

Программа поддерживает эти операции, объектные сметы/ССР, групповые обработки, импорт табличных данных, акты и печатные формы. Маршрут изучения интерфейса: главы 1–13 официального видеокурса, затем 14–20; старые примеры баз в курсе использовать только для освоения операций. [Курс разработчика](https://www.grandsmeta.ru/videograndsmeta).

## РИМ и БИМ

Для **РИМ** выбрать ФСНБ-2022 и совместимую сплит-форму ФГИС ЦС. Создать смету с шаблоном РИМ; подключить автозагрузку текущих цен/индексов; добавить нормы ГЭСН, объёмы, неучтённые ресурсы. Текущая цена ресурса берётся из опубликованных данных; при предусмотренном методикой отсутствии используются базисная цена и индекс соответствующей группы. Отсутствующий ресурс обосновывается по установленной процедуре КА. Проверить незагруженные цены, состав перевозки и коэффициенты. [Инструкция РИМ](https://www.grandsmeta.ru/rim).

Разработчик сопоставляет сплит-формы 2026 года: I квартал — изменения 1–17; II — 1–18/1–18.1; III — 1–19. Это ориентир совместимости программных данных, а не разрешение автоматически переводить любой проект на новейшую редакцию. Дату применения и конкретную сплит-форму проверять по официальным данным проекта. [Таблица соответствия](https://help.grandsmeta.ru/resursno-indeksnyj-metod/normbase-select-rim/sootvetstvie-redaktsii-fsnb-i-split-formy).

Для **БИМ** отдел отдельно фиксирует исходную базу расценок, источник индексов и способ применения: к статьям затрат, видам работ, позициям либо итогу согласно основанию проекта. Не переносить настройки индексов из другой базы/региона. При прямой текущей цене исключить повторную индексацию. Порядок операций изучать в главе 8 [курса](https://www.grandsmeta.ru/videograndsmeta). Здесь БИМ означает базисно-индексный метод; информационная модель BIM — отдельное понятие.

## НР, СП и контроль

Выбрать корректные справочники видов работ, НР/СП и поправок. Проверять привязку каждой позиции и все ручные изменения. Команда **Операции → Экспертиза → Проверка НР и СП** сравнивает со справочными данными или другой сметой. При сравнении с нормативной базой позиции, для которых не найден эталонный вид работ, могут не проходить дальнейшую проверку НР/СП: вручную созданные позиции и КА требуют отдельной проверки. Успешный автоматический отчёт не заменяет её. [Описание проверки](https://help.grandsmeta.ru/nakladnye-raskhody-i-smetnaya-pribyl/proverka-nr-i-sp-na-sootvetstvie-spravochnym-znacheniyam).

## Акты, передача и XML

Для учёта выполнения создавать акт за конкретный период на базе согласованного расчёта, вводить фактическое количество, контролировать предыдущие акты и остаток. По данным выполнения доступны КС-2, ресурсы, М-29; по объекту — КС-3. Правило офиса: ни объём, ни подпись не считать подтверждёнными только потому, что они напечатаны программой. [Разделы 15 и 18 курса](https://www.grandsmeta.ru/videograndsmeta).

Обменный XML ГРАНД-Сметы и XML для экспертизы ГГЭ — разные форматы. Для обычного XML предусмотрено **Данные → Экспорт → Экспорт в XML**: выбрать документы, выполнить проверку мастера, задать папку. Для группы формируются отдельные файлы. [Экспорт XML](https://help.grandsmeta.ru/ob-ekty-i-smety/eksport-smet-v-razlichnye-formaty/eksport-v-format-xml). Версию схемы получателя и формат ГГЭ проверять отдельно; расширения `.xml` недостаточно. Спецификация сметы контракта опубликована отдельно: [XSD разработчика](https://xsd.grandsmeta.ru/sk/defaultpage.html).

Правило выдачи отдела: нативный редактируемый файл, согласованная печатная форма, требуемый XML, исходные обоснования и протокол проверки должны относиться к одной редакции. После экспорта сверить количества, цены, НР/СП и итог; проверить открытие и схему в целевом ПО. Проверка XSD подтверждает структуру, но не правильность сметного решения.

## Практический допуск сотрудника

До самостоятельной выдачи выполнить на лицензированном рабочем месте учебный объект: ВОР → ЛСР РИМ с учебным КАЦ материального ресурса по трём источникам → КА → ОС/ССР → акт → печать/XML → повторное открытие → независимая проверка → восстановление резервной копии. Критерий: все расхождения объяснены, не осталось необоснованных цен и коэффициентов, редакции совпадают. Это внутренний экзамен отдела; сейчас он **не выполнен**. Неустановленные базы и неизвестные лицензии записывать как неизвестные, а не как отсутствующие или имеющиеся.

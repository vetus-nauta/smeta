# Инструментальный процесс существующего локального Сметчика

Этот конспект связывает пять существующих Skills с поддерживаемыми локальными инструментами. Не создаёт нового агента, нормативную базу или новый handoff. Оригиналы сохраняются; рабочие результаты версионируются через Storage Policy/Registry. Перед операцией проверить доступность API и актуальный журнал испытаний: наличие кода и ссылки из Skill не доказывает успешную работу модели.

## Роли и выбор задачи

LOCAL_SMETCHIK принимает поручение, классифицирует входы, выбирает разрешённые инструменты, объясняет выбранные нормативные кандидаты и возвращается к первичным документам при неполноте. DETERMINISTIC_TOOL читает XML/таблицы, нормализует измерители, вычисляет Decimal, проверяет связи и пишет артефакты. CODEX реализует/проверяет инструменты и оценивает локальные результаты. Подготовленный CODEX отчёт не заменяет наблюдаемое исполнение LOCAL_SMETCHIK.

Новая смета требует ВОР/проектных quantities, технологии, норм, ресурсов и цены; СВОР/ИСКЛ без старого УТВ не нужны. Изменение требует baseline и двух ревизий; замена технологии — исключение старой и добавление новой. Аудит читает оригинал и классифицирует расхождения; не правит его. Составление новой сметы должно дать фактический расчётный JSON/XLSX с источниками и открытыми входами, а не только текст замечаний.

## Реальные Python API и CLI

Пути ниже относительно корня репозитория `smeta`; запуски с выходными файлами используют проверенные resolver пути.

| Инструмент | API / CLI | Что возвращает и что проверять |
|---|---|---|
| `tools/estimate_audit.py` | `inspect_file(name, raw)`, `inspect_directory(path)`, `inspection_summary(data)`, `controls(data)`; CLI `directory --output result.json` | Полное извлечение ZIP/XML/XLSX/PDF, raw формулы/cached данные, locators и контрольные находки. OCR_UNVERIFIED требует проверки первичной страницы. Сохранённая print_area не гарантирует охват всех значимых строк |
| `tools/estimate_norms.py` | `catalog()`, `exact_lookup(namespace, revision, code, kind='norm')` | Доступные namespace/revision/source metadata и точный норматив с source_identity, locator, ресурсами и ценами; отсутствие редакции не заменяется другой |
| `tools/estimate_norms.py` | `search_candidates(description, technology='', materials='', unit='', technical_conditions='', namespace=None, revision=None, source_metadata=None, calculation_period=None, limit=10)`; CLI `[description] --namespace ... --revision ... --unit ... --technology ... --materials ... --period YYYY-MM-DD`; `--catalog` | Кандидаты ранжируются по описанию/составу/материалу/условиям и явно сохраняют несовпадение единиц. Это ограниченный текстовый/семантический поиск, не доказательство нормативной применимости. Effective date ≤ период недостаточно для доказательства отсутствия последующих изменений |
| `tools/estimate_norms.py` | `calculation_record(source_identity)`, `norm_to_calculation(record)` | Проверка неизменяемой идентичности записи перед расчётом; адаптация реальных ресурсов/компонентов. Project/неучтённый расход, цена и неизвестная единица остаются missing, не нулём |
| `tools/estimate_calculation.py` | `convert_quantity(request)`, `build_estimate(request, trusted_resolution=None)`, `cost_effect(request)`, `export_xlsx(result, path)`; CLI `request.json --operation convert|compose|effect --output result.json [--xlsx review.xlsx]` | Детерминированный новый расчёт/сценарий: explicit units/scope/evidence, нет повторного включения материалов/НДС/индекса. Результат `NOT_FOR_APPROVAL`, JSON/XLSX, нативный GRAND экспорт не поддерживается |
| `tools/pricing.py` | CLI `quotes.json`; API `normalize(q)` | Проверка структуры цен/налогов/доставки и вычислений по входному источнику; не выдаёт несопоставимое КП за оптимальное |
| `tools/grand_practice.py` | `normalized_volume(physical, measure, mode)`, `change_volume(before, after, same_work=...)`, `remaining_volume(contract, prior, current)`, `coverage(source_ids, output_source_ids)` | Явная нормализация/остаток/покрытие; технологическая замена не превращается в простую дельту одинаковой работы |

Существующий runtime: `/ai/estimates-agent/agent/estimate_workflow.py`, CLI:

```bash
PYTHONPATH=/ai/estimates-agent python3 -m agent.estimate_workflow \
  --input /ai-data/documents/estimates/PROJECT/source.xlsx \
  --query 'Составь проверочный расчёт из этой ВОР с источниками и открытыми данными' \
  --receipt /ai-data/research/estimates/PROJECT/local-receipt.json
```

Модуль запускается с package context через `-m`, поскольку использует относительные imports; окружение Python и зависимости проверить по существующему runtime. CLI параметры `--input`, `--query`, `--receipt` подтверждены исходным кодом. Документальная сессия через существующий gateway сохраняет execution-log с выбором инструмента LOCAL_SMETCHIK и детерминированным результатом. Возможности повторного `investigate`/чтения конкретного документа, расширенного поиска и `compose` в runtime реализуются в существующем модуле; до успешного испытания конкретного маршрута они остаются интеграцией в работе. Не писать PASS по одному наличию функций.

## Перечитывание и нормативный выбор

После обзорного извлечения выбери конкретный файл/вложение/строку/XPath. Перечитай полную нужную позицию, WorksList и ресурсы, если краткий summary потерял технологию, толщину, ресурсный расход или реквизиты. Поиск нормы начинается с операции, механизации, материала, размера, условий и единицы; похожее название — только кандидат. Сохрани причины выбора/отклонения, полный source_identity, namespace/revision/source_id, действующий период и locator. `source_metadata` допускает namespace/revision/source_id/amendments; нет доступного изменения — `NOT_AVAILABLE`, без неявной подмены «самой новой» базой.

## Многораздельная ВОР

`tools/estimate_vor.py: extract_vor(inspection)` читает несколько листов, разделы и повторные заголовки. Все исходные строки сохраняются как принятые либо `rejected_rows` с причиной; превышение 5000 работ прекращает обработку без усечения. Исходные «100 м2» нормализуются один раз в физическую единицу, которая передаётся нормативному поиску. Повторное применение выбора допустимо только при точном равенстве описания, технологии, материалов, условий, физической единицы, нормативной области и исходного раздела. Объёмы и расчёт каждой строки сохраняются отдельно. Текстовое сходство не подтверждает связь позиций.

## Новый ВОР → проверочный расчёт

Проверить ВОР или существующий `engineering-handoff-v1`: quantity_id, object_id, source_hash, drawing_id/page_or_sheet/element_id, revision, unit/dimensions, review_status и дубликаты. AUTO_EXTRACTED/NEEDS_REVIEW не повышаются до HUMAN_VERIFIED моделью. Изменение источника/ревизии требует повторного человеческого принятия через существующий механизм.

У `convert_quantity` задать mode, trace_id, physical_unit, norm_factor и value. Геометрический mode требует relation, input_unit, подтверждённую relation_confirmed и именованные length/width/height с semantic/unit/evidence. Запись «500×200×60» без паспорта не разрешает выбрать первое число как длину: нужны названные оси и источник. cached Result нормы не делить на KUnit повторно; хранить физический и нормативный объёмы отдельно.

`compose`: request `price_basis=BASE_NET`, `mode=BASE_ONLY` или `PREVIEW`, lines с trace_id/scope/quantity/norm, четырьмя компонентами labour/machines/machinist/materials, ресурсами и evidence. Norm содержит code/revision/unit/physical_unit/norm_factor/source/evidence. Коэффициенты/индексы имеют компонент, scope_trace_id, value и evidence. НР/СП — FOT, percent, scope_trace_id и evidence. PREVIEW требует явных индексов всех четырёх компонентов; BASE_ONLY не принимает текущие индексы. НДС задаётся отдельно; отсутствие режима не ноль. ПЗ=labour+machines+materials; machinist уже внутри machines, ФОТ=labour+machinist. Неучтённый ресурс получает подтверждённый проектный расход и цену отдельно; включённый ресурс не получает повторную external_price.

Каждая строка обоснована источником. Любой `applicability_confirmed` из входного JSON игнорируется. Текущие цены PREVIEW рассчитываются только после положительного ответа серверной `trusted_resolution(kind, trace_id, evidence, facts)` для нормы, применимых коэффициентов либо подтверждённого отсутствия дополнительных коэффициентов, индексов, НР и СП; НДС подтверждается отдельно. JSON не может передать функцию проверки. Без такого серверного подтверждения текущая стоимость остаётся неизвестной. Missing поля остаются в результате. Новый составленный JSON/XLSX маркируется NOT_FOR_APPROVAL даже при арифметическом успехе. Это поддерживаемый расчёт для профессиональной проверки, не имитация GSFX/подписи/экспертизы.

`effect` считает условное влияние только при одинаковом ресурсе и единицах old/new, заданных conditions, scope, источнике и price_basis BASE_NET/CURRENT_NET. Ресурсный сценарий не полный пересчёт сметы. Не скрывать неизвестную цену/потребность условным итогом; не заменять исходный УТВ.

Результаты `investigate` включаются в Markdown: документ/позиция, причины, классификация достоверности и открытое влияние на стоимость. Денежное округление HALF_UP до копеек: сумма отображаемых ПЗ, НР и СП даёт строку; сумма строк даёт итог; НДС округляется от этого итога. XLSX содержит числовые суммы и явно обозначает неизвестные значения.

## Приёмка результата

Отдельно проверить охват входов/активных позиций, размерности, формулы, ресурсы/связи, цены/налоги, НР/СП, итоги, ревизии и статус человека. Parse, XSD и нативный пересчёт — разные результаты. Сохранить реальный execution-log и ожидаемые независимые контрольные данные; успешный тест включает LOCAL_SMETCHIK выбор/чтение/вывод, а не полностью подготовленную CODEX подсказку. Нативная ГРАНД-Смета и официальные источники индексов/техчасти не объявляются выполненными без наблюдаемого подтверждения. Исторические частные сметы и поставщики не публикуются в Git вместе с этим общим конспектом.

# Проверка перед выпуском

09.09.2026. Для каждой применимой проверки: PASS / FAIL / NOT_CHECKED / N/A с основанием. «Проверено всё» без доказательств не принимается.

| Блок | Проверка | Свидетельство |
|---|---|---|
| Задание | Цель, объект, регион, ценовая зона, дата, метод и состав результата определены | Паспорт и исходное поручение |
| Объёмы | Полнота, отсутствие дублей, единицы, формулы, соответствие ревизии проекта | Ссылка до листа и позиции ВОР |
| Нормы | Шифр, состав работ, техчасть, исключённые/заменённые ресурсы, действующее изменение базы | Нормативная матрица, параметры ПО |
| Условия | Коэффициенты имеют основание и корректную базу применения; совместимость проверена | Формулы, пункты документов, условия объекта |
| Цены | Период и территория соответствуют; источник цены установлен по каждому ресурсу | ФГИС ЦС/документ индекса/КАЦ |
| КАЦ | Техническая и коммерческая сопоставимость, подлинные доказательства, обоснование выбора | Оригиналы предложений и таблица |
| Налоги | Режим и ставка на нужную дату подтверждены; цена с НДС не смешана с ценой без НДС | КП, договор, налоговое основание |
| Начисления | НР/СП, транспорт, ЗСР, временные, зимние, прочие затраты не задвоены и применимы | Основания и базы начисления |
| Итоги | Независимый пересчёт сумм и уровней итогов, правила округления | Расчёт проверяющего и расхождения |
| Форматы | Печатный результат совпадает с исходником; XML валиден по требуемой версии XSD | Отчёт проверки/импорта и сравнение |
| Выпуск | Закрыты блокирующие замечания; файлы согласованной версии; опись и хеши | Решение начальника и manifest.json |

## Существенность замечаний

- **BLOCKER:** неизвестный обязательный вход; вымышленные доказательства; неверная база/период/метод; неподтверждённая итоговая цена; невалидный обязательный формат. Выпуск итогового продукта не допускается.
- **MAJOR:** влияет на деньги, объём, обязательное содержание или возможность проверки. Исправить и перепроверить до выпуска.
- **MINOR:** оформление без влияния на расчёт. Начальник может выпустить с явно перечисленными ограничениями, если это соответствует поручению.

Черновик с открытыми вопросами можно отдать пользователю как отдельный согласованный результат. Для КАЦ при недостаточных данных сначала требуется решение пользователя о способе их получения/применения и составе результата по office/workflow.md, раздел 1.1. Проверяющий проверяет наличие такого решения и соответствие ему; надпись «черновик» не разрешает самостоятельно подставлять значения, исключать позиции или выпускать неполный КАЦ вместо заказанного полноценного документа.

## Особые запреты

Нельзя оценивать достоверность только по расширению файла, цифре итогов, цвету строки в программе или отсутствию ошибок экспорта. Нельзя объявлять документ прошедшим экспертизу без соответствующего заключения. При работе только с PDF проверка внутренних формул и настроек исходного файла отмечается NOT_CHECKED.

## Усиление после разбора практики

Проверять охват исходных ID в обе стороны, включая весь согласованный диапазон и вхождения слоёв. Объяснять баланс добавленных/исключённых элементов, а не только общий счётчик строк. Не путать полноту реестра и полноту денежного итога. После исправления повторно сверять охват, объёмы, состав, ресурсы, комментарии, ссылки и отображение.

Для СВОР/УТВ использовать knowledge/change-estimates.md; для кода/ресурса knowledge/fer-fssc.md; для формата knowledge/grand-xml-verified.md. Не удалять штатные NotCount и не перенумеровывать SysID ради «чистого» отчёта. Импорт/автокоррекция проверяются сравнением исходного и полученного результата.

При существенной неопределённости объёмов, технологии или цены применять knowledge/cost-uncertainty.md. Сценарий хранится как аналитическое приложение до подтверждения исходных данных; вероятности без модели и произвольная надбавка вместо решения вопроса не допускаются.

## КАЦ: коды и география

По поручению Алексея проверять каждую группу КСР по официальному каталогу и характеристикам, включая ранее заполненные коды. Проверять населённый пункт, код субъекта и привязку к поставщику у каждого вложенного предложения XML, затем выбор основной строки. В протоколе — охват, пропуски, ошибки, источники и невыполненные проверки отображения. Подробно: knowledge/kac-codes-and-localities.md.

## Раздельные результаты контроля КАЦ

Проверять полноту по [матрице обязательных данных](kac-required-data.md), а не по числу непустых ячеек. Отдельно оценивать извлечение из КП, техническую сопоставимость, единицы, арифметику, КСР, реквизиты, XML/XSD, импорт/пересчёт и приложения. PASS переноса не закрывает качество источника или импорта. Неисправленная унаследованная ошибка XSD остаётся FAIL для этой схемы. Согласованные пустые группы допускаются в оговорённой рабочей выдаче, но не означают полноту итогового расчёта.

# Сметчик изменений

Корень офиса: `/home/alexey/Groot/smetchik`; канонический навык — `skills/smeta-changes/SKILL.md` в `vetus-nauta/smeta`. Прочитай паспорт, `knowledge/change-estimates.md` и `knowledge/practical-controls.md`.

Сначала установи статус УТВ, ревизии проекта/СВОР, реальный смысл колонок, единицы, знак исключения и нормативное окружение. УТВ в изученном корпусе — название исходной сметы, считающейся утверждённой авторами; это не доказательство утверждения и не универсальная форма. При другом смысле уточни по текущим исходникам.

Изучи весь оговорённый диапазон книги, включая нижние и скрытые строки, составные ячейки и формулы. Ограничивай лист только по заданию. Цвет, жирность, буквы столбцов и номер строки не заменяют содержательную классификацию.

Для сопоставимой работы вычисляй новое минус старое, не повторяй вычитание из уже готовой колонки дельты. Замена технологии требует связанных ветвей исключения и добавления даже при нулевой разности площади. Не дели на старый нулевой объём для пропорционального переноса ресурсов.

Веди устойчивую карту СВОР → изменение → блок/слой → позиции «плюс»/«минус». На уменьшение идентифицируй исходную позицию и исключаемую часть; не подменяй её новой расценкой. На увеличение подбирай технологию и состав, включая действительно неучтённые ресурсы без дубля основного материала. Кандидаты ФЕР/ФССЦ проверяются по `knowledge/fer-fssc.md`.

Сохраняй физический объём, измеритель, формулу и результат. Не исправляй `/100`, `NotCount`, `SysID`, `MaxSysID` или `Quantity` массовой эвристикой. Для XML читай `knowledge/grand-xml-verified.md` и схему конкретного формата. Визуальный слой и денежный учёт проверяются отдельно.

Выход: таблица охвата, карта изменений, проекты требуемых смет, перечень нерешённого и независимая проверка. Неполная цена не становится полной сметой от наличия всех строк. При недоступной ГРАНД-Смете не заявляй успешный импорт/печать.

Старые расчёты, КП и КАЦ из рассмотренного Drive-корпуса пользователь запретил использовать как эталон/основу до отдельного решения. Заимствуются только проверенные методы и уроки. Исходные приватные материалы не публикуются; изменения навыка фиксируются в GitHub с CHANGELOG, установленная копия обновляется после проверки.
